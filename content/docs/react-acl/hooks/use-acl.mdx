title: useAcl
description: Read the ACL loading state and run role and permission checks in code with isAuthorized.
---

`useAcl` returns the `isAuthorized` function and `loading` flag from the nearest [`AclProvider`](/docs/react-acl/components/acl-provider). [`HasAccess`](/docs/react-acl/components/has-access) is built on it.

Use `HasAccess` when you show or hide a piece of markup. Use `useAcl` when you need the answer as a value: filtering a list of actions, disabling instead of hiding, choosing a redirect, or checking access inside an event handler.

## Import

```tsx
import { useAcl } from "@piplup/react-acl";
```

## isAuthorized

```ts
type IsAuthorized = (check: {
  roles?: (number | string)[] | number | string;
  permissions?: (number | string)[] | number | string;
  validationMode?: { roles?: "all" | "any"; permissions?: "all" | "any" };
}) => boolean;
```

It follows the same rules as `HasAccess`: roles and permissions must both pass, an omitted or empty list passes, and each list defaults to `any`. See [how access is decided](/docs/react-acl/components/has-access#how-access-is-decided).

Unlike the `HasAccess` props, `roles` and `permissions` also accept a single value, so `isAuthorized({ permissions: "post:delete" })` works without wrapping it in an array.

## Loading

`isAuthorized` returns `false` for every call while the provider's `loading` is `true`, even for a check with no requirements. Check `loading` first, so you can tell "still loading" apart from "denied":

```tsx
function DeleteButton() {
  const { isAuthorized, loading } = useAcl();

  return (
    <button disabled={loading || !isAuthorized({ permissions: "post:delete" })}>
      Delete
    </button>
  );
}
```

`isAuthorized` changes identity when the provider's `roles`, `permissions` or `loading` change. If you use it inside `useEffect`, `useMemo` or `useCallback`, list it as a dependency so the result is recomputed after a role change.

<Callout type="warn">
  `useAcl` throws `AclProvider must be rendered as parent before using useAcl` when it is called outside an `AclProvider`. This also applies to `HasAccess`.
</Callout>
