---
title: useMuiXDateTimePickerAdapter
description: Returns adapter props for MUI X DateTimePicker with React Hook Form, including time rules such as minTime, maxTime, minutesStep and shouldDisableTime.
---

`useMuiXDateTimePickerAdapter` connects a field to React Hook Form and returns props you spread onto MUI X's `DateTimePicker`. It's what [`MuiXDateTimePickerElement`](/docs/rhf-adapters/mui-x-date-pickers/components/mui-x-date-time-picker-element) uses internally.

Use the element for most forms. Use the hook when one kind of date-time field repeats across your app with the same rules, such as booking slots limited to opening hours, and you want those rules and messages defined once in your own component.

## Import

```tsx
import { useMuiXDateTimePickerAdapter } from '@piplup/rhf-adapters/mui-x-date-pickers';
```

This `MeetingField` accepts times from 09:00 to 17:00 in 15 minute steps, on any day from tomorrow. Type a time such as 08:30 or 10:07 and submit to see the time rules.

## How it works

Value handling, the text field wiring (`slotProps.textField`, `composeHelperText`) and the "closing the picker counts as a blur" behavior are the same as in [`useMuiXDatePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-date-picker-adapter). What differs is validation.

**Date checks, then time checks.** The hook runs MUI X's `validateDateTime`. It first runs every date check from the DatePicker hook (`minDate`, `maxDate`, `shouldDisableDate` and so on, with the same keys and default messages). If those pass, it checks the time, in this order:

| Key                         | Fails when                                           | Default message                               |
| --------------------------- | ---------------------------------------------------- | --------------------------------------------- |
| `minTime`                   | The time is before `minTime`                         | Time is earlier than the minimum allowed time |
| `maxTime`                   | The time is after `maxTime`                          | Time is later than the maximum allowed time   |
| `disableFuture`             | The value is after the current moment                | Future date is not allowed                    |
| `disablePast`               | The value is before the current moment               | Past date is not allowed                      |
| `shouldDisableTime-hours`   | `shouldDisableTime(value, "hours")` returns `true`   | Hour is disabled                              |
| `shouldDisableTime-minutes` | `shouldDisableTime(value, "minutes")` returns `true` | Minute is disabled                            |
| `shouldDisableTime-seconds` | `shouldDisableTime(value, "seconds")` returns `true` | Second is disabled                            |
| `minutesStep`               | The minutes are not a multiple of `minutesStep`      | Minute step is not valid                      |

Only the first failing check is reported. Override any message through `messages`, using the key from the table.

**`disablePast` and `disableFuture` work to the minute.** The date check compares by day, and the time check compares against the current time. So with `disablePast`, 08:00 today fails if it is already 10:00.

**`minTime` and `maxTime` ignore the date by default.** Only the time of day is compared, so `minTime` set to 09:00 means "09:00 or later on any day". Set `disableIgnoringDatePartForTimeValidation: true` to compare the full date and time instead. To express "not before this exact moment", pass the same value to `minDate` and `minTime` with that flag. The [MobileDateTimePicker example](#mobiledatetimepicker) below shows it.

<Callout type="warn">
  The hook and the picker decide this flag differently. The hook uses the value you pass. MUI X's
  `DateTimePicker` ignores that prop and turns full date comparison on whenever `disablePast`,
  `disableFuture`, `minDateTime` or `maxDateTime` is set. If you combine a time-of-day `minTime`
  with `disablePast`, the picker lets users choose 07:00 tomorrow and the form then rejects it. Keep
  them aligned: use time-of-day limits without `disablePast`/`disableFuture`, or set the flag
  together with `disablePast` for an exact-moment limit.
</Callout>

The hook does not read `minDateTime` or `maxDateTime`. If you pass them straight to the picker, the picker greys out those times but the form still accepts a typed value outside the range. Use `minTime`/`maxTime` with the flag above so the rule is validated too.

**The rules also drive the picker UI.** The validation props are returned with the adapter props, so spreading them onto `DateTimePicker` also disables the matching days, hours and minutes in its views (subject to the flag difference above). The form-level check still matters for typed values and for values set with `reset` or `setValue`.

<Callout type="warn">
  In TypeScript, `minDate` and `maxDate` are required props of the date-time hooks, unlike the
  date-only hooks. Pass real limits, as the example does. If they are missing at runtime, the hook
  falls back to the `LocalizationProvider` defaults (1900-01-01 and 2099-12-31).
</Callout>

## Desktop, mobile and static versions

`DateTimePicker` picks its layout from the device: a popover when the pointer is precise, such as a mouse, and a dialog on touch screens. MUI X also has three versions with a fixed layout, and each has a hook, imported from `@piplup/rhf-adapters/mui-x-date-pickers`:

| Hook                                  | Spread onto                                           | Errors shown by       |
| ------------------------------------- | ----------------------------------------------------- | --------------------- |
| `useMuiXDesktopDateTimePickerAdapter` | `DesktopDateTimePicker`, a popover on every device    | `slotProps.textField` |
| `useMuiXMobileDateTimePickerAdapter`  | `MobileDateTimePicker`, a dialog on every device      | `slotProps.textField` |
| `useMuiXStaticDateTimePickerAdapter`  | `StaticDateTimePicker`, always visible, no text field | you render them       |

The desktop and mobile hooks call `useMuiXDateTimePickerAdapter` with the same props and return its result unchanged, so everything above applies to them. The static hook validates the same way, but returns the error for you to render.

### DesktopDateTimePicker

`useMuiXDesktopDateTimePickerAdapter` returns props for `DesktopDateTimePicker`. Use the hook when you want a desktop date-time field with your own rules built in, for example one that always opens as a popover and blocks hours your team is not available.

This `CallbackField` only accepts hours between 08:00 and 20:00, skips the 13:00 lunch hour, and rejects past times. Open the picker to see the blocked hours, or type 13:15 and submit.

**`shouldDisableTime` runs once per time view.** The hook calls `shouldDisableTime(value, "hours")`, then `"minutes"`, then `"seconds"`, and reports the first one that returns `true` under its own key: `shouldDisableTime-hours`, `shouldDisableTime-minutes` or `shouldDisableTime-seconds`. Check the `view` argument and only return `true` for the view your rule is about, as the example does. A rule that ignores `view` always fails on hours first, so only the hours message ever shows.

The same function greys out options in the popover's time columns, so users mostly hit the message when they type a time.

**Errors and blur.** `error`, `helperText` and `onBlur` go to the text field through `slotProps.textField`. You can pass `slotProps.textField` as a function of the picker's owner state, as the example does. The hook calls it and merges the result with its own props: an error message wins over your `helperText`, and both `onBlur` handlers run. Leaving the text field and closing the popover both mark the field as touched.

### MobileDateTimePicker

`useMuiXMobileDateTimePickerAdapter` returns props for `MobileDateTimePicker`. Use the hook when you build a touch-first date-time field with rules that depend on the current moment, such as a pickup time that must be at least two hours away.

This `PickupField` rejects anything earlier than two hours from now and only accepts half-hour slots. Open the dialog to see the earlier times greyed out, or submit without a value to see the `required` message.

    },

**An earliest date and time.** The hook does not read `minDateTime`. To validate "not before this moment", the example passes the same value to `minDate` and `minTime` and sets `disableIgnoringDatePartForTimeValidation: true`:

- `minDate` rejects earlier days with the `minDate` message.
- `minTime` with the flag compares the full date and time, so an earlier time on the same day fails with the `minTime` message. Without the flag, `minTime` would act as a daily opening time: a limit of 14:30 would also reject 09:00 tomorrow.
- `disablePast` is set as well. MUI X's picker ignores the flag you pass and only compares full dates when `disablePast`, `disableFuture`, `minDateTime` or `maxDateTime` is set. With `disablePast`, the dialog greys out the same times the form rejects.

Create the limit once, for example with `useState(() => dayjs().add(2, "hour"))`. A new `dayjs()` on every render moves the limit forward while the user fills the form, so a value that passed a moment ago can fail on submit.

**Errors and blur.** The text field gets `error`, `helperText` and `onBlur` through `slotProps.textField`. The hook also wraps `onClose`, so closing the dialog marks the field as touched, whether the user confirms or cancels. With `mode: "onTouched"`, opening and cancelling the dialog on an empty required field shows the `required` message straight away.

### StaticDateTimePicker

`useMuiXStaticDateTimePickerAdapter` returns props for `StaticDateTimePicker`. `MuiXStaticDateTimePickerElement` shows no validation message at all. Use the hook when the user needs to see why a value was rejected: you get the error state and message back and decide where to render them.

This `PublishAtField` schedules a post on the hour or half hour, up to two weeks ahead. Pick tomorrow, leave the time as it is, and submit to see the message rendered under the picker.

    },

/>

**No `slotProps.textField`.** Unlike the DateTimePicker hook, this one does not take `slotProps` and does not build a text field slot. It returns `error`, `helperText` and `required` as plain values. `StaticDateTimePicker` has no props for them, so take them off the result before spreading and render them yourself, as the example does with `FormHelperText`. With `composeHelperText: true`, `helperText` holds the error message.

**No touched state.** The hook ignores any `onBlur` you pass and has no `onClose` to wrap. The returned `onBlur` is React Hook Form's, but `StaticDateTimePicker` never calls it. The field is never marked as touched, so `mode: "onBlur"` and `mode: "onTouched"` do not validate it before the first submit. Use the default `onSubmit` mode or `onChange`.

**Every pick changes the value.** The form value updates on each selection in the picker, not when the user presses an action button. Picking a day with no value yet keeps the current time of day, so in the example it usually fails the `:00`/`:30` rule until a minute is chosen. The example hides the action bar with `slotProps={{ actionBar: { actions: [] } }}` for that reason.

**Ref.** React Hook Form's ref and your `ref` are merged and attached to the picker's root element. There is no input to focus, so `setFocus` and `shouldFocusError` do nothing for this field.
