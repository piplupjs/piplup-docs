---
title: useMuiXTimePickerAdapter
description: Returns adapter props for MUI X TimePicker with React Hook Form, including minTime, maxTime, minutesStep and shouldDisableTime.
---

`useMuiXTimePickerAdapter` connects a field to React Hook Form and returns props you spread onto MUI X's `TimePicker`. It's what [`MuiXTimePickerElement`](/docs/rhf-adapters/mui-x-date-pickers/components/mui-x-time-picker-element) uses internally.

Use the element for most forms. Reach for the hook when you want your own time field component, for example one that always enforces opening hours or a minute step, or one that shares form wiring across several pickers. This page describes the time validation that all time hooks share.

## Import

```tsx
import { useMuiXTimePickerAdapter } from '@piplup/rhf-adapters/mui-x-date-pickers';
```

This `ShiftStartField` only accepts times between 08:00 and 18:00 on the quarter hour, with its own messages. Submit it empty, or type `07:30` or `09:10`, to see the validation.

## How it works

**Value.** The field value is passed to the picker as-is, with `undefined` converted to `null` so the picker stays controlled. Pass `transform` if your form stores something other than a date object.

**Validation props reach the picker too.** `minTime`, `maxTime`, `minutesStep`, `shouldDisableTime`, `disablePast`, `disableFuture` and `disableIgnoringDatePartForTimeValidation` are returned by the hook, so the picker greys out the same times that validation rejects. `disablePast` and `disableFuture` default to `false`.

**Validation.** The hook runs MUI X's `validateTime` on every non-empty value. Empty values pass; add `required` to reject them. Checks run in this order and only the first failure is reported:

| Order | Key                         | Fails when                                            | Default message                               |
| ----- | --------------------------- | ----------------------------------------------------- | --------------------------------------------- |
| 1     | `invalidDate`               | the value is not a valid date, e.g. a half-typed time | Date is not a valid date                      |
| 2     | `minTime`                   | the time is before `minTime`                          | Time is earlier than the minimum allowed time |
| 3     | `maxTime`                   | the time is after `maxTime`                           | Time is later than the maximum allowed time   |
| 4     | `disableFuture`             | the value is after now                                | Future date is not allowed                    |
| 5     | `disablePast`               | the value is before now                               | Past date is not allowed                      |
| 6     | `shouldDisableTime-hours`   | `shouldDisableTime(value, "hours")` returns `true`    | Hour is disabled                              |
| 7     | `shouldDisableTime-minutes` | `shouldDisableTime(value, "minutes")` returns `true`  | Minute is disabled                            |
| 8     | `shouldDisableTime-seconds` | `shouldDisableTime(value, "seconds")` returns `true`  | Second is disabled                            |
| 9     | `minutesStep`               | the minutes are not a multiple of `minutesStep`       | Minute step is not valid                      |

`required` uses "Please fill out this field." The messages above are the exact default text.

**Time of day only.** `minTime` and `maxTime` compare only the time of day, so the date part of the values you pass is ignored. Set `disableIgnoringDatePartForTimeValidation` to compare full date-times instead. `disablePast` and `disableFuture` always compare against the current date and time.

**Timezone.** Validation uses the `timezone` prop when given, otherwise the timezone of the value.

**Custom messages.** Pass any key from the table in `messages`, as a string or a function. A function receives the value, and for `minTime`, `maxTime` and `minutesStep` also the limit, for example `(value, minTime) => "Open from " + minTime.format("HH:mm")`. `invalidDate` is typed as a function only, so write it as `invalidDate: () => "Enter a valid time"`.

**Errors and helper text.** The returned `slotProps.textField` sets `error` and `helperText` from the field state and merges your own `slotProps.textField` (an object or a function). The hook has no top-level `helperText` prop; put your hint in `slotProps.textField.helperText`. With `composeHelperText: true` an error message replaces that hint while the field is invalid. Without it, only the `error` state is applied.

**Blur and touched.** The returned `slotProps.textField` calls React Hook Form's `onBlur`, so typing a time and tabbing away marks the field as touched. The returned `onClose` also calls `onBlur` and then your own `onClose`, so closing the picker counts as a blur too.

**Your own `rules.validate`.** A `validate` function or object in `rules` runs next to the built-in time validation, not instead of it.

**Refs.** React Hook Form's ref, merged with your `inputRef`, is returned as `inputRef`, so `setFocus` and focus-on-error move focus to the input. The hook's second argument becomes `ref` on the picker root.

## Variants

The other time hooks use the same validation and messages. They differ in where errors can render and how a field becomes touched:

| Hook                                                                                                                                  | Text field    | Errors shown by              | Touched on                 |
| ------------------------------------------------------------------------------------------------------------------------------------- | ------------- | ---------------------------- | -------------------------- |
| [`useMuiXDesktopTimePickerAdapter`](#desktoptimepicker)                                                                               | yes           | `slotProps.textField`        | input blur or picker close |
| [`useMuiXMobileTimePickerAdapter`](#mobiletimepicker)                                                                                 | yes           | `slotProps.textField`        | input blur or dialog close |
| [`useMuiXStaticTimePickerAdapter`](#statictimepicker)                                                                                 | no            | you render them              | never                      |
| [`useMuiXTimeFieldAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-time-field-adapter)                                 | yes, no popup | `error` / `helperText` props | input blur                 |
| [`useMuiXTimeClockAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-time-clock-adapter)                                 | no            | you render them              | blur inside the clock      |
| [`useMuiXDigitalClockAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-digital-clock-adapter)                           | no            | you render them              | blur inside the clock      |
| [`useMuiXMultiSectionDigitalClockAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-multi-section-digital-clock-adapter) | no            | you render them              | blur inside the clock      |

## Desktop, mobile and static versions

`TimePicker` picks its layout from the device: a popover when the pointer is precise, such as a mouse, and a dialog on touch screens. MUI X also has three versions with a fixed layout, and each has a hook, compared in the [Variants](#variants) table above.

The desktop and mobile hooks call `useMuiXTimePickerAdapter` with the same props and return its result unchanged, so everything above applies to them. The static hook validates the same way, but returns the error for you to render.

### DesktopTimePicker

`useMuiXDesktopTimePickerAdapter` returns props for `DesktopTimePicker`. Use it when you build your own desktop time field, for example one that always blocks certain hours. Pick it over `useMuiXTimePickerAdapter` when you want the desktop popover on every device, including touch screens.

This `MeetingTimeField` rejects any time in the 12:00 hour. The popover greys that hour out, but you can still type `12:30 PM` into the field and submit to see the error.

What differs is the component you spread it onto:

- `TimePicker` switches between the desktop and mobile layouts with the `@media (pointer: fine)` media query. `DesktopTimePicker` always uses the desktop layout.
- The desktop popover shows a `DigitalClock` (one column) or a `MultiSectionDigitalClock` (one column per section), depending on the views and `timeSteps`. Both disable the options that `minTime`, `maxTime`, `minutesStep` and `shouldDisableTime` reject, because the hook returns those props.
- The text field is the main way to enter a time. A typed time never goes through the disabled options in the popover, so validation is what rejects it.

**`shouldDisableTime` and its message.** Validation calls `shouldDisableTime(value, view)` with `"hours"`, then `"minutes"`, then `"seconds"`, and reports the first view that returns `true`. Return `true` only for the view you mean, and override the matching key. The example checks `view === "hours"`, so its error comes from `shouldDisableTime-hours`; the default for that key is "Hour is disabled".

### MobileTimePicker

`useMuiXMobileTimePickerAdapter` returns props for `MobileTimePicker`. Use it when you build your own touch-first time field, for example a same-day booking field that always rejects times that have passed. Pick it over `useMuiXTimePickerAdapter` when you want the dialog on every device, including desktops with a mouse.

This `PickupTimeField` only accepts times later today. Open the dialog and pick a time that has already passed, then submit.

    },

What differs is the component you spread it onto:

- `TimePicker` picks the mobile layout only when the `@media (pointer: fine)` media query does not match. `MobileTimePicker` always uses it.
- The hours, minutes and seconds views render as an analog `TimeClock` inside a dialog, not the digital lists of the desktop popover. The clock disables the hours and minutes that `minTime`, `maxTime`, `minutesStep` and `shouldDisableTime` reject.
- Errors still render under the text field, through `slotProps.textField`, not inside the dialog.
- The returned `onClose` runs when the dialog closes, which calls React Hook Form's `onBlur` and marks the field as touched. With `mode: "onBlur"` or `"onTouched"`, validation runs right after the user closes the dialog.

**`disablePast` and `disableFuture` compare the full date and time.** Unlike `minTime` and `maxTime`, they do not ignore the date part. A value picked in the dialog keeps the date of the current value, or today's date when the field is empty, so in the example "past" means earlier today. If the form value carries another date, the check uses that date.

### StaticTimePicker

`useMuiXStaticTimePickerAdapter` returns props for `StaticTimePicker`. `MuiXStaticTimePickerElement` renders the picker only, so it never shows an error message. Use the hook when you want the always-visible picker and also want to show validation errors next to it.

This `ReportTimeField` requires a time no later than 20:00 and shows the error below the picker. Submit without picking a time, or pick 21:00, to see it.

<Demo
  tabs={[
    {
      label: 'Custom field',
      path: 'demo/adapters/mui-x-date-pickers/static-time-picker/custom-hook.tsx',
    },
    {
      label: 'Element source',
      path: 'https://raw.githubusercontent.com/piplupjs/piplup-react-hook-form/refs/heads/main/packages/rhf-adapters/src/mui-x-date-pickers/static-time-picker/element.tsx',
    },
  ]}
/>

- There is no `slotProps`, `inputRef` or `onClose` in the result, and the hook does not accept them.
- The result has plain `error` and `helperText` values. With `composeHelperText: true`, `helperText` is the current error message, or `undefined` when the field is valid. There is no `helperText` prop, so put any hint in your own markup, as the example does with `helperText || "..."`.
- The hook's second argument is merged with React Hook Form's ref and returned as `ref`.

Take `error` and `helperText` out of the result before spreading it, and render them yourself, for example with `FormHelperText`. The element drops them for the same reason.

<Callout type="warn">
  A static picker is never closed and has no input to blur, so nothing calls the returned `onBlur`
  and the field is never marked as touched. `mode: "onBlur"` and `"onTouched"` first validate on
  submit. Use `mode: "onChange"` to show errors while the user picks.
</Callout>

**When the value changes.** By default `StaticTimePicker` uses `displayStaticWrapperAs="mobile"`: an analog clock with a toolbar. The value reaches the form through `onChange` each time the user changes the clock, not only when they accept it.
