`MuiXDatePickerElement` is the MUI X `DatePicker` connected to React Hook Form. It stores the
picked date, turns the picker's own limits, such as `minDate` and `disablePast`, into form
validation with readable messages, and shows errors as the picker's helper text. New to the
adapters? Start with [Using MUI with React Hook Form](/docs/react-hook-form-mui).

## Import

```tsx
import { MuiXDatePickerElement } from "@piplup/rhf-adapters/mui-x-date-pickers";
```

Like every MUI X picker, the element needs a `LocalizationProvider` above it with a date library
adapter. The examples on this page use Dayjs.

## What gets stored

The field holds a date object from your adapter: a Dayjs object with `AdapterDayjs`, a `Date` with
`AdapterDateFns`, and so on. An empty picker stores `null`, so use `null` in `defaultValues`.

Most APIs want a string, so format the date when you submit rather than storing strings in the
form. Keeping a date object lets the picker validate and compare dates.

## Date limits are validation too

`minDate`, `maxDate`, `disablePast`, `disableFuture` and the `shouldDisable*` functions do two
things on this element: they limit what the user can pick, and they become React Hook Form
validation. A date typed by hand outside the range fails on submit with its own message. This
booking form requires a check-in date that isn't in the past, and a check-out after it:

```tsx
import { LocalizationProvider } from "@mui/x-date-pickers";
import { AdapterDayjs } from "@mui/x-date-pickers/AdapterDayjs";
import { MuiXDatePickerElement } from "@piplup/rhf-adapters/mui-x-date-pickers";
import type { Dayjs } from "dayjs";
import { useForm } from "react-hook-form";

type Booking = { checkIn: Dayjs | null; checkOut: Dayjs | null };

export function BookingForm() {
  const { control, handleSubmit, watch } = useForm<Booking>({
    defaultValues: { checkIn: null, checkOut: null },
  });
  const checkIn = watch("checkIn");

  return (
    <LocalizationProvider dateAdapter={AdapterDayjs}>
      <form
        noValidate
        onSubmit={handleSubmit((values) =>
          console.log({
            checkIn: values.checkIn?.format("YYYY-MM-DD"),
            checkOut: values.checkOut?.format("YYYY-MM-DD"),
          }),
        )}
      >
        <MuiXDatePickerElement
          control={control}
          name="checkIn"
          label="Check-in"
          required
          disablePast
          messages={{
            required: "Pick a check-in date",
            disablePast: "Check-in can't be in the past",
          }}
        />
        <MuiXDatePickerElement
          control={control}
          name="checkOut"
          label="Check-out"
          required
          minDate={checkIn ?? undefined}
          messages={{ minDate: "Check-out must be after check-in" }}
        />
      </form>
    </LocalizationProvider>
  );
}
```

Each limit has a default message that `messages` can replace:

| Limit | Default message |
| --- | --- |
| `minDate` | Date must be later than the minimum allowed date |
| `maxDate` | Date should be earlier than the maximum allowed date |
| `disablePast` | Past date is not allowed |
| `disableFuture` | Future date is not allowed |
| `shouldDisableDate` | Date is not allowed |
| `shouldDisableMonth` | Month is not allowed |
| `shouldDisableYear` | Year is not allowed |
| An unparseable typed date | Date is not a valid date (`messages.invalidDate`) |

An empty picker passes these checks, so add `required` when a date is mandatory. Your own
`rules.validate` functions still run alongside them.

`MuiXDatePickerElement` supports all standard props of the MUI X DatePicker component, along with additional adapter-specific props. For a complete list of available DatePicker properties, refer to the MUI X Date Pickers [API documentation](https://mui.com/x/api/date-pickers/date-picker/).

> The `ref` is forwarded to the underlying `<DatePicker />` component.

## Notes

- For custom picker UIs, build on `useMuiXDatePickerAdapter`.
- The error state and message go to the picker's text field through `slotProps.textField`. Your
  own `slotProps.textField` still applies; a validation error takes precedence over its
  `helperText`.
- `timezone` is passed to both the picker and its validation.
