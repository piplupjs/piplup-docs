title: useMuiRadioGroupAdapter
description: Returns props that connect an MUI RadioGroup to React Hook Form, with null for no selection and transforms for non-string values.
---

`useMuiRadioGroupAdapter` connects an MUI `RadioGroup` to a React Hook Form field and returns props you spread onto the group. The `Radio` children stay plain MUI radios. It's what [`MuiRadioGroupElement`](/docs/rhf-adapters/mui-material/components/mui-radio-group-element) uses internally.

Use the element for a simple list of options. Reach for the hook when the group, its label and its error message should be one reusable component, or when the stored value isn't a string, like the boolean in the example below. For radios that aren't inside a `RadioGroup`, see [`useMuiRadioAdapter`](/docs/rhf-adapters/mui-material/hooks/use-mui-radio-adapter).

## Import

```tsx
import { useMuiRadioGroupAdapter } from "@piplup/rhf-adapters/mui-material";
```

## Usage

A yes/no question stored as `true` or `false`, starting as `null`. The transform converts between the booleans in the form and the `"true"`/`"false"` strings the radios use. Submit without answering to see the error.

## How it works

**One registration for the group.** The hook registers the field once and the `RadioGroup` tells its radios which one is checked. Compare this with [`useMuiRadioAdapter`](/docs/rhf-adapters/mui-material/hooks/use-mui-radio-adapter), where every radio is wired to the field separately.

**Empty values.** An `undefined` field value is passed to the group as `null`, so the group stays controlled with nothing selected. On change, the hook stores the selected radio's value, or `null` if that value is `""` or `undefined`.

**Values are strings.** `RadioGroup` reports the selected radio's value as a string, so by default the field ends up holding strings. To store numbers or booleans, override both directions with `transform`: `input` turns the field value into the string the radios use, and `output` receives `(event, value)` and returns what to store. Each key you set replaces the default for that direction, so handle `undefined` and `null` in your own `input`.

**Inside a `FormControl`.** If you don't pass `disabled` or `required`, the hook takes them from the surrounding MUI `FormControl`.

**Errors.** `RadioGroup` doesn't render errors. Put the returned `error` on a `FormControl` and render `helperText` in a `FormHelperText`. With `composeHelperText: true`, `helperText` is the field's error message, falling back to your `helperText` when there's no error.

**What's returned.** `name`, `value`, `onChange`, `onBlur`, `ref`, `disabled`, `required`, `error`, `helperText`, `className`, `style` and `classes`. `title` is not returned.

<Callout type="warn">
  React Hook Form's `required` rule treats `false` as missing. If you store a boolean, `required` rejects the "No" answer. Use `rules.validate` to check for `null` instead, as the demo does.
</Callout>

<Callout type="warn">
  `RadioGroup` has no `error` or `helperText` props. Remove them from the returned object before spreading, as the demo and the element do.
</Callout>
