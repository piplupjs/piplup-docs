title: useMuiIconButtonAdapter
description: Returns props for an MUI IconButton that submits or resets a React Hook Form form and disables itself from form state.
---

`useMuiIconButtonAdapter` returns props you spread onto MUI's `IconButton` so it can submit or reset a React Hook Form form and disable itself from the form state. It's what [`MuiIconButtonElement`](/docs/rhf-adapters/mui-material/components/mui-icon-button-element) uses internally.

The hook behaves exactly like [`useMuiButtonAdapter`](/docs/rhf-adapters/mui-material/hooks/use-mui-button-adapter). Icon buttons usually sit inside compact controls such as search bars, toolbars and table rows, so the hook is handy for building those as one component with the form wiring included.

## Import

```tsx
import { useMuiIconButtonAdapter } from "@piplup/rhf-adapters/mui-material";
```

## Usage

A search bar with two icon buttons. The search button uses `disableOnError`, so it's disabled while the query is shorter than three characters. The clear button is `type="reset"` and restores the empty default value.

## How it works

For the full behavior (form state subscription, the disabling table, reset on `type="reset"`, class names, helper text) see [How it works on the button hook page](/docs/rhf-adapters/mui-material/hooks/use-mui-button-adapter#how-it-works). Points that come up with icon buttons:

**`disableOnError` follows the whole form.** The error state is `true` whenever the form's `isValid` is `false`. The demo has one field, so that's the query. The form uses `mode: "onChange"`, so the error message appears as you type and the button re-enables as soon as the query is valid. An empty query is valid here because there's no `required` rule.

**Disabling on one field only.** If the form has other fields, `isValid` covers them too. Pass your own `error` to base the state on one field instead. It replaces the `isValid` check:

```tsx
const { errors } = useFormState({ control, name: "query" });

const adapter = useMuiIconButtonAdapter<FormValues, HTMLButtonElement>({
  control,
  type: "submit",
  disableOnError: true,
  error: !!errors.query,
});
```

`errors` only holds a field once it has been validated, so with this approach untouched fields don't disable the button.

**Accessible name.** The adapter doesn't add a label. An icon has no text, so give each `IconButton` an `aria-label`, as the demo does.

<Callout type="warn">
  `IconButton` has no `error` or `helperText` props. Remove them from the returned object before spreading it, as the demo and the element do.
</Callout>
