---
title: useMuiRatingAdapter
description: Returns props that connect an MUI Rating to React Hook Form, with null for no rating and min/max turned into validation rules.
---

`useMuiRatingAdapter` connects an MUI `Rating` to a React Hook Form field and returns props you spread onto it. It's what [`MuiRatingElement`](/docs/rhf-adapters/mui-material/components/mui-rating-element) uses internally.

Use the element when stars alone are enough. Reach for the hook when the rating needs things the element doesn't render: a legend, a word label for the hovered star, or an error message under the stars.

## Import

```tsx
import { useMuiRatingAdapter } from "@piplup/rhf-adapters/mui-material";
```

## Usage

A required rating with a label that follows the hovered star. Click the selected star again to clear it, then submit to see the error.

## How it works

**Empty value is `null`.** An `undefined` field value reaches `Rating` as `null`, so it stays controlled and shows no stars. On change, the hook stores the number `Rating` reports. When the user clicks the selected star again, `Rating` reports `null` and that's what gets stored. `required` rejects `null`.

**`max` and `min`.** `max` is returned and sets the number of stars, as on `Rating`. Both `max` and `min` also become validation rules:

| Prop | Rule | Default message |
| --- | --- | --- |
| `min` | Rating must be at least `min` | Value must be `min` or later. |
| `max` | Rating must be at most `max` | Value must be `max` or earlier. |

The `max` rule can't fail, since `Rating` doesn't go past `max`. The `min` rule is useful for "at least 2 stars", but the default wording is generic, so set `messages.min`. A `min` of `0` adds no rule, and an empty (`null`) rating passes the `min` rule, so add `required` if a rating must be given. `min` isn't a `Rating` prop; it only affects validation.

**Errors.** `Rating` doesn't show errors. The hook returns `error` and `helperText`; render them in a `FormHelperText`. With `composeHelperText: true`, `helperText` is the field's error message, falling back to your `helperText` when there's no error.

**Blur.** The returned `onBlur` marks the field as touched when focus leaves the rating's radio inputs.

<Callout type="warn">
  `Rating` has no `error` or `helperText` props. Remove them from the returned object before spreading, as the demo and the element do.
</Callout>

<Callout type="warn">
  If you pass a function as `messages.min` or `messages.max`, it's called with an array holding the limit (for example `[2]`), not the number itself. It works in a template string but not in arithmetic. Use a plain string message to be safe.
</Callout>
