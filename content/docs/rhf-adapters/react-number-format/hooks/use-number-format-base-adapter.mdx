`useNumberFormatBaseAdapter` connects a field to React Hook Form and returns props you spread onto `NumberFormatBase` from `react-number-format`. It's what [`NumberFormatBaseElement`](/docs/rhf-adapters/react-number-format/components/number-format-base-element) uses internally, and [`useNumericFormatAdapter`](/docs/rhf-adapters/react-number-format/hooks/use-numeric-format-adapter) and [`usePatternFormatAdapter`](/docs/rhf-adapters/react-number-format/hooks/use-pattern-format-adapter) are thin wrappers around it.

Use the element for one-off fields. Reach for the hook when you write your own `format` function (card expiry, time, custom IDs) and want a reusable field with that format, its rules and its `TextField` styling baked in.

## Import

```tsx
import { useNumberFormatBaseAdapter } from "@piplup/rhf-adapters/react-number-format";
```

## Usage

This `CardExpiryField` formats digits as `MM/YY`, renders a `TextField`, and rejects incomplete or past dates. Type `0120` and submit to see the expiry rule; the alert shows what the form stores.

## How it works

**What gets stored.** The hook listens to `onValueChange`, not `onChange`, and writes `values.value` to the form: the unformatted string that `removeFormatting` returns. `NumberFormatBase`'s default `removeFormatting` keeps digits only, so typing `04/28` stores `"0428"`. Pass your own `removeFormatting` if separators should survive.

To store something else, pass `transform.output`. It receives the same arguments as `onValueChange` (`values`, `sourceInfo`) plus the current value, so `(values) => values.formattedValue` stores `"04/28"` instead.

**What gets displayed.** The form value is passed back as `value`, with `undefined` turned into `""` so the input stays controlled. `NumberFormatBase` treats a string `value` as already formatted: it runs `removeFormatting` on it, then `format`. A number `value` goes straight to `format`. If you store something your `removeFormatting` can't read back, also pass `transform.input`.

**Validation.** All rules apply to the stored value, not to what the user sees:

| Prop | Checks | Default message |
| --- | --- | --- |
| `required` | value is not empty | Please fill out this field. |
| `minLength` / `maxLength` | length of the stored string | Please lengthen this text to *n* characters or more / Please shorten this text to *n* characters or less. |
| `pattern` | stored string matches | Please match the requested format. |
| `min` / `max` | stored value as a number | Value must be *n* or later. / Value must be *n* or earlier. |

Override any of them through `messages`. For checks that span parts of the value, like the expiry date above, use `rules.validate`.

**Errors and helper text.** `error` and `helperText` are only returned when you set `composeHelperText: true`. Then `helperText` is the error message when the field is invalid and your `helperText` otherwise. Without it, neither prop is returned, because the default `NumberFormatBase` renders a plain `<input>`, which doesn't accept them.

**Ref and blur.** The returned `getInputRef` is React Hook Form's field ref merged with any `getInputRef` you pass. `onBlur` marks the field as touched and then calls your `onBlur`.

<Callout type="warn">
  With `customInput={TextField}`, `react-number-format` attaches `getInputRef` to the `TextField` root, not the `<input>`. React Hook Form then can't move focus to this field when validation fails.
</Callout>
