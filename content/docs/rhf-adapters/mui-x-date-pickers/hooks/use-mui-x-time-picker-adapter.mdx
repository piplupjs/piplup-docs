---
title: useMuiXTimePickerAdapter
description: Returns adapter props for building custom MUI X TimePicker integrations with React Hook Form, including minTime, maxTime, minutesStep and shouldDisableTime validation.
---

`useMuiXTimePickerAdapter` connects a field to React Hook Form and returns props you spread onto MUI X's `TimePicker`. It's what [`MuiXTimePickerElement`](/docs/rhf-adapters/mui-x-date-pickers/components/mui-x-time-picker-element) uses internally.

Use the element for most forms. Reach for the hook when you want your own time field component, for example one that always enforces opening hours or a minute step, or one that shares form wiring across several pickers. This page describes the time validation that all time hooks share.

## Import

```tsx
import { useMuiXTimePickerAdapter } from "@piplup/rhf-adapters/mui-x-date-pickers";
```

## Usage

This `ShiftStartField` only accepts times between 08:00 and 18:00 on the quarter hour, with its own messages. Submit it empty, or type `07:30` or `09:10`, to see the validation.

The hook must run inside a `LocalizationProvider`, because it reads the date adapter to validate values.

## How it works

**Value.** The field value is passed to the picker as-is, with `undefined` converted to `null` so the picker stays controlled. Pass `transform` if your form stores something other than a date object.

**Validation props reach the picker too.** `minTime`, `maxTime`, `minutesStep`, `shouldDisableTime`, `disablePast`, `disableFuture` and `disableIgnoringDatePartForTimeValidation` are returned by the hook, so the picker greys out the same times that validation rejects. `disablePast` and `disableFuture` default to `false`.

**Validation.** The hook runs MUI X's `validateTime` on every non-empty value. Empty values pass; add `required` to reject them. Checks run in this order and only the first failure is reported:

| Order | Key | Fails when | Default message |
| --- | --- | --- | --- |
| 1 | `invalidDate` | the value is not a valid date, e.g. a half-typed time | Date is not a valid date |
| 2 | `minTime` | the time is before `minTime` | Time is later than the maximum allowed time |
| 3 | `maxTime` | the time is after `maxTime` | Time is earlier than the minimum allowed time |
| 4 | `disableFuture` | the value is after now | Future date is not allowed |
| 5 | `disablePast` | the value is before now | Past date is not allowed |
| 6 | `shouldDisableTime-hours` | `shouldDisableTime(value, "hours")` returns `true` | Hour is disabled |
| 7 | `shouldDisableTime-minutes` | `shouldDisableTime(value, "minutes")` returns `true` | Minute is disabled |
| 8 | `shouldDisableTime-seconds` | `shouldDisableTime(value, "seconds")` returns `true` | Second is disabled |
| 9 | `minutesStep` | the minutes are not a multiple of `minutesStep` | Minute step is not valid |

`required` uses "Please fill out this field." The messages above are the exact default text. Note the wording of the `minTime` and `maxTime` defaults: the `minTime` message mentions the maximum, and the `maxTime` message mentions the minimum. Set your own messages for both when you use those props, as the example does.

**Time of day only.** `minTime` and `maxTime` compare only the time of day, so the date part of the values you pass is ignored. Set `disableIgnoringDatePartForTimeValidation` to compare full date-times instead. `disablePast` and `disableFuture` always compare against the current date and time.

**Timezone.** Validation uses the `timezone` prop when given, otherwise the timezone of the value.

**Custom messages.** Pass any key from the table in `messages`. Use strings. `invalidDate` is typed as a function only, so write it as `invalidDate: () => "Enter a valid time"`.

<Callout type="warn">
  A function message is called with a single array argument, `[value, limit]` (for example `[value, minTime]`), not with separate arguments as its type suggests. `(value) => value.format("HH:mm")` throws because `value` is that array. Prefer plain strings.
</Callout>

<Callout type="warn">
  If you pass your own `rules.validate`, the built-in time validation above is not added. Validate times yourself in that case.
</Callout>

**Errors and helper text.** The returned `slotProps.textField` sets `error` and `helperText` from the field state and merges your own `slotProps.textField` (an object or a function). The hook has no top-level `helperText` prop; put your hint in `slotProps.textField.helperText`. With `composeHelperText: true` an error message replaces that hint while the field is invalid. Without it, only the `error` state is applied.

**Blur and touched.** The returned `onClose` calls React Hook Form's `onBlur` and then your own `onClose`, so closing the picker marks the field as touched.

<Callout type="warn">
  Unlike [`useMuiXDatePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-date-picker-adapter), this hook does not attach `onBlur` to the text field. If a user types a time and tabs away without opening the picker, the field is not marked as touched, and `mode: "onBlur"` or `"onTouched"` validation waits until submit. Use `mode: "onChange"` or `"all"` if typed times should be checked before submit.
</Callout>

**Refs.** React Hook Form's ref, merged with your `inputRef`, is returned as `inputRef`, so `setFocus` and focus-on-error move focus to the input. The hook's second argument becomes `ref` on the picker root.

## Variants

The other time hooks use the same validation and messages. They differ in where errors can render and how a field becomes touched:

| Hook | Text field | Errors shown by | Touched on |
| --- | --- | --- | --- |
| [`useMuiXDesktopTimePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-desktop-time-picker-adapter) | yes | `slotProps.textField` | picker close |
| [`useMuiXMobileTimePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-mobile-time-picker-adapter) | yes | `slotProps.textField` | dialog close |
| [`useMuiXStaticTimePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-static-time-picker-adapter) | no | you render them | never |
| [`useMuiXTimeFieldAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-time-field-adapter) | yes, no popup | `error` / `helperText` props | input blur |
| [`useMuiXTimeClockAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-time-clock-adapter) | no | you render them | blur inside the clock |
| [`useMuiXDigitalClockAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-digital-clock-adapter) | no | you render them | blur inside the clock |
| [`useMuiXMultiSectionDigitalClockAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-multi-section-digital-clock-adapter) | no | you render them | blur inside the clock |
