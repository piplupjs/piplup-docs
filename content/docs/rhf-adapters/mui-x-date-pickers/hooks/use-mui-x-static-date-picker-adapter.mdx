`useMuiXStaticDatePickerAdapter` returns React Hook Form props for MUI X's `StaticDatePicker`, the always-visible date picker. It's what [`MuiXStaticDatePickerElement`](/docs/rhf-adapters/mui-x-date-pickers/components/mui-x-static-date-picker-element) uses internally.

The element validates but never shows a message. Use the hook when the picker is the main input on the page, such as a booking screen, and users need to see why their date was rejected.

## Import

```tsx
import { useMuiXStaticDatePickerAdapter } from "@piplup/rhf-adapters/mui-x-date-pickers";
```

## Usage

This `TourDateField` blocks sold-out days and dates more than 60 days ahead. Submit without picking a day to see the message rendered under the picker.

## How it works

Validation is the same as in [`useMuiXDatePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-date-picker-adapter), with the same rules, keys and default messages. The difference is that there is no text field and no popup to attach errors and blur to.

**Error display is up to you.** The hook does not build `slotProps.textField`. It returns `error`, `helperText` and `required` as plain values, and `StaticDatePicker` has no props for them. Take them off the result before spreading, then render them, as the example does with `FormHelperText`. Set `composeHelperText: true` so that `helperText` holds the error message.

**No hint text.** The hook does not accept a `helperText` prop (it is cleared even if passed), so `helperText` in the result is either the error message or `undefined`. Write any hint text directly in your component.

**No touched state.** Any `onBlur` you pass is ignored. The returned `onBlur` is React Hook Form's, but `StaticDatePicker` never calls it, so the field is never marked as touched. In `onBlur` or `onTouched` mode it is only validated after the first submit.

**Ref.** React Hook Form's ref and your `ref` are merged and attached to the picker's root element. There is no input to focus, so `setFocus` and `shouldFocusError` have no effect on this field.

The validation props are also spread onto the picker, so sold-out days and dates past `maxDate` are greyed out in the calendar. The form-level check still catches values set through `defaultValues`, `reset` or `setValue`.
