title: useMuiXDesktopTimePickerAdapter
description: Returns adapter props for building custom MUI X DesktopTimePicker integrations with React Hook Form, where users mostly type times into the field.
---

`useMuiXDesktopTimePickerAdapter` connects a field to React Hook Form and returns props you spread onto MUI X's `DesktopTimePicker`. It's what [`MuiXDesktopTimePickerElement`](/docs/rhf-adapters/mui-x-date-pickers/components/mui-x-desktop-time-picker-element) uses internally.

Use the hook instead of the element when you build your own desktop time field, for example one that always blocks certain hours. Pick this variant over [`useMuiXTimePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-time-picker-adapter) when you want the desktop popover on every device, including touch screens.

## Import

```tsx
import { useMuiXDesktopTimePickerAdapter } from "@piplup/rhf-adapters/mui-x-date-pickers";
```

## Usage

This `MeetingTimeField` rejects any time in the 12:00 hour. The popover greys that hour out, but you can still type `12:30 PM` into the field and submit to see the error.

## How it works

This hook calls `useMuiXTimePickerAdapter` with the same props and returns its result unchanged. Value handling, the validation order, default messages and `slotProps.textField` merging are described on the [`useMuiXTimePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-time-picker-adapter#how-it-works) page.

What differs is the component you spread it onto:

- `TimePicker` switches between the desktop and mobile layouts with the `@media (pointer: fine)` media query. `DesktopTimePicker` always uses the desktop layout.
- The desktop popover shows a `DigitalClock` (one column) or a `MultiSectionDigitalClock` (one column per section), depending on the views and `timeSteps`. Both disable the options that `minTime`, `maxTime`, `minutesStep` and `shouldDisableTime` reject, because the hook returns those props.
- The text field is the main way to enter a time. A typed time never goes through the disabled options in the popover, so validation is what rejects it.

**`shouldDisableTime` and its message.** Validation calls `shouldDisableTime(value, view)` with `"hours"`, then `"minutes"`, then `"seconds"`, and reports the first view that returns `true`. Return `true` only for the view you mean, and override the matching key. The example checks `view === "hours"`, so its error comes from `shouldDisableTime-hours`; the default for that key is "Hour is disabled".

<Callout type="warn">
  Typing in the field does not mark it as touched. Only closing the popover calls React Hook Form's `onBlur`. With `mode: "onBlur"` or `"onTouched"`, a typed time is first validated on submit, not when the user tabs away. Use `mode: "onChange"` or `"all"` if typed times should be checked before submit.
</Callout>
