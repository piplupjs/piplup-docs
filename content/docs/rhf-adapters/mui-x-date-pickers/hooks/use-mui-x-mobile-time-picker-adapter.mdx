title: useMuiXMobileTimePickerAdapter
description: Returns adapter props for building custom MUI X MobileTimePicker integrations with React Hook Form, where the time is chosen on an analog clock in a dialog.
---

`useMuiXMobileTimePickerAdapter` connects a field to React Hook Form and returns props you spread onto MUI X's `MobileTimePicker`. It's what [`MuiXMobileTimePickerElement`](/docs/rhf-adapters/mui-x-date-pickers/components/mui-x-mobile-time-picker-element) uses internally.

Use the hook instead of the element when you build your own touch-first time field, for example a same-day booking field that always rejects times that have passed. Pick this variant over [`useMuiXTimePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-time-picker-adapter) when you want the dialog on every device, including desktops with a mouse.

## Import

```tsx
import { useMuiXMobileTimePickerAdapter } from "@piplup/rhf-adapters/mui-x-date-pickers";
```

## How it works

This hook calls `useMuiXTimePickerAdapter` with the same props and returns its result unchanged. Value handling, the validation order, default messages and `slotProps.textField` merging are described on the [`useMuiXTimePickerAdapter`](/docs/rhf-adapters/mui-x-date-pickers/hooks/use-mui-x-time-picker-adapter#how-it-works) page.

What differs is the component you spread it onto:

- `TimePicker` picks the mobile layout only when the `@media (pointer: fine)` media query does not match. `MobileTimePicker` always uses it.
- The hours, minutes and seconds views render as an analog `TimeClock` inside a dialog, not the digital lists of the desktop popover. The clock disables the hours and minutes that `minTime`, `maxTime`, `minutesStep` and `shouldDisableTime` reject.
- Errors still render under the text field, through `slotProps.textField`, not inside the dialog.
- The returned `onClose` runs when the dialog closes, which calls React Hook Form's `onBlur` and marks the field as touched. With `mode: "onBlur"` or `"onTouched"`, validation runs right after the user closes the dialog.

**`disablePast` and `disableFuture` compare the full date and time.** Unlike `minTime` and `maxTime`, they do not ignore the date part. A value picked in the dialog keeps the date of the current value, or today's date when the field is empty, so in the example "past" means earlier today. If the form value carries another date, the check uses that date.
